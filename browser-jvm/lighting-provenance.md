# Native lighting service qualification

The service in `lighting-kernel.js` and `lighting-natives.js` implements a bounded, genuine part of the installed lighting solver. It is not a complete lighting-engine replacement. It is connected to original startup through the audited cell-loading boundary; Ingame remains unqualified. Neither module changes original Java classes, `LightingJNI.init`, game settings, or saves.

## Protected reference inputs

The native reference inspected and tested on 2026-10-16 is the installed x86-64 `Lighting64.dll`, SHA256 `1866188d8e253de521ba208f06f1db9b9019f333162ff3c31dd83506fafee773`. Its original `projectzomboid.jar` has SHA256 `e1a69eb743ede60b213a0fe7f8b83d4fcab773036d256cc4543a336f3b058a33`.

Portable Ghidra12.1.4 through REA supplied static native control-flow evidence. Proprietary binaries, decompiler output, snapshots, and raw inspection logs remain in ignored local storage. No proprietary source or native result tables are included in these modules.

`LightingQualification.java` is authored test transport. On the reference JVM it loads only the actual lighting DLL and calls the original Java native declarations. It does not start a game, server, Lua runtime, world simulation, or engine worker thread. In the browser it calls those same original native declarations through registered host implementations. The existing prepared Java17 SDK view supplies the original game classes with its separately documented compatibility adaptations.

| `0x180004d50` | Ordered directional propagation through actual square adjacency. |
| `0x180004800` | Shortest-path relaxation for duplicate light identifiers and ordered light records. |
| `0x180001f90`, `0x180004800` | Five result slots per square. Overflow replaces the first greatest distance/radius ratio only when the candidate ratio is strictly smaller; it preserves the replaced slot rather than sorting results. |

| `0x1800060e0`, `0x1800046b0` | Cardinal vision-matrix checks, plus both cardinal edges and the diagonal bit from both endpoints for a diagonal step. |
| `0x1800041a0`, `0x180003970` | Near-detection visibility, retained seen history, cardinal-neighbor darkness averaging, integer light attenuation, per-channel RGB maximum, and float32 darkness multiplication. |
| `0x180009c30`, `0x180012aa0` | Relative LOS-cache invalidation on a floored player-square change or the original cache signal; actual worker timestamp/global invalidation dispatch, including the full static-light calculation requested by global invalidation. |
| `0x1800090d0`, `0x180009370`, `0x180009950` | Three shared-corner maximum passes, including native mutation/traversal order. |

| `0x180003310` | Door/window/curtain ray classification, retaining the native three-valued result rather than treating it as a boolean. |

The payload is the original49-int format: visibility bits; packed center RGB; darkness and target darkness scaled100000; ambient level; eight packed vertex colors; result-light count; then up to five6-int records. Unused words in a caller's Java array remain unchanged. Result-light Z retains the original native32 offset.

Native `squareSet` at0x180015b50 stores incoming light level at square+0x18, but worker0x180008650 resets that field on every present square before sky seeding. The public fixture supplies nonzero outdoor levels even with sky0 and verifies the resulting native reset; those inputs are not treated as replacement ambient seeds. Room metadata affects sky seeding and visible-room collection. Building metadata is retained. The ordinary static-light constructor ignores its building argument and initializes native restrictions to-1. Room-light rectangles use their separate native seeding and publication lifecycle. Frame RGB values are clamped by the native center-color path; ambient/night/view packet values do not become extra multipliers in this qualified packed output. The varied-frame references preserve that distinction.

The main write queue and worker buffer remain separate when a second update arrives before the worker finishes. Deferred geometry accumulates, and the worker can complete while another main-thread draft is open. Native ready chunks inherit readback square-dirty bytes at worker time before marking changed payloads or submitted geometry. The native0xea50 swap also recycles unread chunk-dirty maps from the old readback buffer into the next worker buffer. Consequently, consuming dirty bits before versus after the worker can change the next publication's dirty state even when lighting values match. The service preserves both buffer rules. Diagnostics retain only the last completed update and clear it on destroy.

At the JNI boundary, unsupported inputs reject with a real Java `UnsupportedOperationException`; invalid protocol state rejects with `IllegalStateException`. Successful native calls retain their synchronous fast path. A raw JavaScript exception would stop the CheerpJ Java thread before its catch/finally blocks, so the adapter constructs and throws the actual Java exception through the calling library. The browser qualification requires both Java catch clauses and finally cleanup to run before the normal native comparisons.

## Qualified scope and explicit rejection

The native service accepts one player moving horizontally on a fixed native floor, a fixed rectangular region of at most13x13 chunks with up to169 loaded chunks, and an ordinary static-light registry without the former seven-source guard. A full169-chunk plane and twelve contributing registered sources have direct native evidence. Indoor and outdoor squares, room/building metadata, sky, static closed doors, intact unbarricaded windows and open north/west curtains now have native/browser evidence. Its level-major representation covers native levels0..63; the direct native/browser world and vertical fixtures qualify levels32..34. Each chunk supplies its own minimum/maximum level. Explicit null squares remain absent, while up/down adjacency, stairs and all27 vision-matrix bits participate in the original algorithms. It retains unchanged chunks when original Java stops submitting geometry and accepts selective changed-chunk updates. Previously seen squares remain seen after geometry changes with the original cache-invalidation signal.

Global registration count and five per-square result slots are different quantities: the original registry grows dynamically, while five is the recovered native result format and replacement algorithm. Inactive sources and sources unresolvable in a retained scene contribute no records. More than five coincident source lights still reject until native source-cell overflow is separately qualified. The service does not discard upper-floor lamps or select a sorted nearest-five list.

Changed vision geometry, ray-blocking objects or stair state requires the original LOS-cache invalidation signal. Native cached LOS for such changes without that signal is not ported; the update rejects before publication. Deferred sky and perception headers remain attached to the pending worker update, including a later publication which submits no replacement header.

The bounded region is at most104x104 squares, with nonnegative chunk coordinates through65535. Actual loaded geometry may be sparse throughout that declared region. The near-detection distance may vary from0 through20, and the vision-cone threshold from-1 through1; direction normalization and far-field cone tests follow the native calculation. Inputs are checked for finite values, integer bounds, geometry, duplicate lights, and valid transmission tuples before a staged region update can replace retained or published state. Changing an established chunk's level extent remains explicit unsupported.

Frame RGB modifiers, ambient and night inputs may vary within0..1; view distance must be positive and no greater than maximum view, which is bounded at256. Light-source update may be100 or0; fatigue remains0 and four player flags remain false. A pending zero source-update header requires global invalidation on the worker call; calculation without that signal rejects before changing computed results, dirty maps or readiness. Positive headers preserve the previously qualified worker path. Source-update metadata follows its own pending/deferred header, including empty publications and a worker completing inside another main draft. The original LOS cache-cleared input may be true or false. Packed sky may be zero or a24-bit RGB value. Outdoor sky propagation below native level32 remains unqualified. These guards describe the admitted inputs; the service does not rewrite game values to fit them.

Endpoint transmission is qualified in three separate branches: monochrome sky with grayscale filters, colored sky without active transmission, and colored point-light filters with sky0. The native ambient solver seeds from a pointer-hashed set and replaces whole RGB values when any channel improves. Competing colored paths can therefore differ between native allocations. Colored sky with active transmission and non-grayscale ambient filters reject explicitly; per-channel maxima are not substituted to force determinism.

Explicit unsupported handlers throw for scrolling/resizing, unqualified object states and thumpables, temporary/torch lights, player level transitions and fractional player levels. Player positions outside the region or on absent squares of nonempty geometry reject before replacing retained or published state. The seven legacy scalar readback getters also reject until independently qualified; the packed readback used by the tested path is implemented. Visible-room output follows native unsigned64-bit ordering and preserves unused Java long-array elements. All50 original native method names have either one of34 implemented handlers or one of16 explicit unsupported handlers. There is no white-light or empty-success fallback.

Packed readback before a worker buffer has actually been published rejects explicitly. The native DLL can expose uninitialized storage in that phase, so deterministic zero payloads are not a native contract. Reading an explicitly absent square inside a registered chunk level likewise rejects: native null-square readback was observed to return uninitialized words. Null geometry is qualified by its effect on present neighboring squares, which are the squares consumed by the original Java caller.

## Java17 native module loading

The [official CheerpJ native-library guide](https://cheerpj.com/docs/guides/implementing-native-libraries) documents loading a JavaScript module with original `System.loadLibrary` and `java.library.path`. An isolated standard-Java probe succeeds under CheerpJ4.3 Java8 with a real module-provided native result. The same probe under Java17, and unchanged original `LightingJNI.init`, fail with `Missing import: JVM_LoadLibrary` before the service module imports.

A diagnostic override of `jdk.internal.loader.NativeLibraries.load` also intercepted built-in `jimage` loading during JDK bootstrap and was rejected. The qualified fix leaves that original native method intact: `native-library-loader.js` supplies the missing `JVM_LoadLibrary` C import in CheerpJ4.3's existing runtime export/import map. It delegates the actual native path and continuation to the existing `cj3LoadLibrary`, using its NUL-terminated length sentinel. That runtime loader performs the actual read, module import, native registration, suspension and handle return. Existing built-in loading, symbol lookup and original Java bookkeeping remain in control. An existing implementation is preserved.

`Lighting64.js` exports a fresh real backend's JNI map. CheerpJ imports service modules through blob URLs, so its dependency uses an absolute same-origin URL. A private relative-import failure is preserved separately; no successful load is reported when that module fails. The public verifier exercises actual initialization and all three native comparisons through this module. This adapter is qualified against CheerpJ4.3 Java17 runtime exports, which are not a documented stable public API; requalify it on runtime updates. No Java initialization flag, game method body or installed library is patched.

Native functions 0x5d80/0x5d60 build the union of both endpoint cardinal bits. Point propagation (0x4d50) and cardinal vertex neighbors (0x90d0/0x9370/0x9950) consume that combined field. Diagonal vertex neighbors and darkness averaging retain the directed field; vertical behavior is unchanged. The west-target-bit fixture exposes 12 pre-fix packed-word differences, and a complementary east-source-bit/radius1 fixture exposes four vertex differences. Both now match. An explicit null endpoint also matches all 63 present payloads and prevents propagation across absent geometry. The five earlier publication/dirty-state protocols pass after the correction.

## Ordinary static registry and source order (2026-10-28)

The original addLight constructor ignores the building argument, stores the active flag and grows its registry dynamically. Duplicate identifiers throw IllegalStateException("duplicate light id"); removeLight and setLightActive on unknown identifiers throw IllegalStateException("unknown light id"). Main publication snapshots active state; worker calculation reads shared RGB. Removing a source after main publication leaves the queued pointer alive for that calculation, with removal visible to a later main generation. The host retains object identity across those queues and delays new per-player registration as in the native worker. Sources outside a scene's grid or absent loaded levels retain registry ownership but supply no source records.

Native chunk storage at0x1800023d0 uses y+8*x, while point-source seeding at0x180008744 converts its iteration index to x=i&7,y=i>>3. Point-source traversal is therefore y-outer/x-inner, independently of LOS traversal. Correcting only that seed order removes record-slot permutations which center RGB alone did not detect. Seven twelve-source lifecycle snapshots, repeated with building77 and-1, match all43,904 packed words; a fourteen-source outside-grid/absent-level case has no effect on all3,136 baseline words. The original five per-square slots and eviction rule are unchanged. Bootstrap's1,078,784-word comparison remains exact. Room/temporary/torch lights, scrolling/resizing, changed established level spans and other explicit capability rejections remain unqualified.

## Ordinary room-light rectangles (2026-10-28)

The separate room registry preserves addRoomLight's two signed 64-bit IDs and original rectangle. The native rectangle seeder uses each present clipped square as a source of the same room identifier, radius7, RGB229/216/209 and the packed room-source flag. Building/room metadata are stored, but the qualified native seeding path does not use them as an identity filter. This is not a center/radius substitute for the rectangle. Active state is copied by main publication; removing the registry entry after main publication leaves the queued room alive. New room registration enters the per-player list directly after bootstrap, unlike the ordinary static source's additional registration queue. Both families remain gated by original first-player/header readiness.

Duplicate IDs throw IllegalStateException("duplicate room-light id"); unknown toggle/removal IDs throw IllegalStateException("unknown room-light id"). Twenty-six initialized native/adapter snapshots match81,536 words exactly: metadata variants, clipped rectangles, overlapping room sources with a point source, off/on/late toggle/removal and first initialized black-to-lit timing. Uninitialized native first-buffer words are not fabricated. Static43,904-word and bootstrap1,078,784-word comparisons still pass. More than five coincident static sources remain explicitly rejected; the existing native five-slot eviction handles mixed qualified source records. Temporary lights, torches, scrolling/resize, established level-span changes and remaining unsupported methods stay outside this closure.


## Ordered lighting movement and retained buffers (2026-10-28)

Native JNI scrollLeft/Right/Up/Down at 0x1800151b0/15250/152f0/15110 enqueue command types 0/1/2/3. Worker 0x18000c400 applies them to its chunk-pointer grid: 0x2ad0/2bc0/2cd0/29e0 discard the outgoing strip, retain overlapping chunk objects, change the chunk origin and mark the map dirty. Teleport 0x180017280 queues/coalesces type7; worker 0x3230 clears chunk ownership and sets its destination. Readback origin moves only at a later main publication. chunkLightingDone 0x135c5 uses published origin fields plus the ready-byte grid; accepting merely the projected bounds would wrongly skip incoming geometry. Map-dirty processing at 0xa109..a11a calls 0xe9f0 to set indexed dirty bytes.

The focused data-only fixture uses a 3-by-3 chunk region, a colored native point source and a directional cone to distinguish retained seen history and world source coordinates. Seven cases qualify 56 readback phases/21,805 packed words and 63 main readiness phases/1,575 booleans. The overwritten-teleport fixture first projects A and submits geometry while a worker is busy, then changes the same queued command to B: geometry submitted at A keeps world coordinates and only its intersection survives at B. Command revision snapshots preserve this behavior without treating queue length as command identity. Forty-four native absent-chunk stale-word reads are excluded; no absent square data is synthesized. Resize remains rejected.
