# RakNet source and build boundary

The preparer requires the existing Emscripten 3.1.74 SDK and official source files in ignored `.tools/raknet-1a169895/`. It downloads or installs nothing. Obtain `Source/*.cpp` and `Source/*.h` from facebookarchive/RakNet commit `1a169895a900c9fc4841c556e16514182b75faf8`; the 264 exact file identities and Git blob IDs are in `raknet-sources.json`. The upstream BSD notice and additional patent grant are preserved verbatim in `RAKNET-LICENSE.txt` and `RAKNET-PATENTS.txt` and copied beside generated artifacts.

Call `prepareRakNetRuntime('target/browser-jvm/raknet')` from the build owner. The output must be a contained workspace target subdirectory. The preparer verifies all original hashes, copies sources to the owned output, and makes exactly two byte-pinned compatibility changes: exclude unused Linux sys/io.h under Emscripten in FileList.cpp; compare a pointer to nullptr instead of false in ReplicaManager3.cpp. It compiles all 110 upstream translation units with real pthread support, no feature disabling, and no undefined-symbol relaxation. Generated source, module, WASM, build log and hash manifest stay untracked. Existing compiler prerequisites are not a substitute for obtaining the pinned source set.

Serve generated `raknet-engine.mjs`/`.wasm` (and any emitted worker asset) beside `raknet-runtime.js`. The runtime descriptor loader imports `RakNet64.js` and `ZNetNoSteam64.js` from the configured origin; both depend on the same module owner. Compile the authored `port.host.BrowserZNet` helper into the Java entry archive. No original game method is changed.

The owner awaits real full-engine factory/static initialization and verifies actual shared memory/pthread identity. Production runs no codec comparison suite. BitStream exports are ownership-checked, bounded component qualification hooks against upstream codec operations; the verifier uses the same built artifact. Real peer factory/vtable linkage preserves the full candidate engine but no Java peer native is provided. Empty RakNet JNI exports are truthful only after real engine initialization, because the shipped DLL itself has no JNI exports.

This requires actual crossOriginIsolated and SharedArrayBuffer. Hosting headers and startup-controller integration are deliberately separate. The optional credentialless helper must be installed before CheerpJ4.3 creates its exact official c.html downloader frame, restored at owner disposal, and used only on a browser exposing the native capability. It neither rewrites the runtime nor changes the separate /files IndexedDB service. Public profile headers are unchanged by these files.

Qualified scope is library/static initialization, source/native-compared BitStream behavior, original non-Steam library publication, and two ZNet logging callbacks. Shipped RakNet revision and protocol equivalence are UNKNOWN. No peer, Startup, UDP/network/proxy, Steam service, whole GameWindow startup, global destructor or full shutdown is admitted. Future peer/socket natives remain absent and must not return fabricated readiness. Worker termination at owned JVM disposal is not global C++ shutdown.

Private startup composition reports explicit original Java success, but its strict request-failure gate remains raw FAIL: valid responses followed by precleanup canceled Fetch requests of unresolved ownership. No cancellation waiver is part of the production implementation or its evidence.

The successful Java callback path is qualified. The installed native callback describes and clears Java exceptions; that exceptional path is not qualified here, and the Java helper propagates the actual callback failure.
