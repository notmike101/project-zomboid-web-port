# Architecture decisions

## 2026-10-11 — M1 integrated proof

Scope: a technical prototype, not a playable port or fidelity claim. The full destination remains M0–M5 in ROADMAP.md. This increment imports real PNG gameplay imagery, renders it through WebGPU, owns movement/action state in WASM, and loads an ES-module mod that changes movement speed.

- **Rust 1.96.0, wasm32-unknown-unknown, no crate dependencies.** Installed Windows toolchain, small reproducible C ABI, native rule tests, no generated JavaScript glue. C++ would add compiler setup; wgpu would add unnecessary bindings for this first renderer.
- **Direct JavaScript WebGPU**, one production backend. Real texture uploads, WGSL shaders, render pipeline and queue submission. No WebGL fallback. JavaScript owns browser UI, GPU resources, mod callbacks and asset decoding; Rust owns coordinates, movement target/direction, speed, bounds, tick and cancellation.
- **Single WASM instance on main thread** at fixed 60 Hz. Frame deltas capped at 100 ms; pause/hidden tabs cancel movement and discard backlog, no offline catch-up. Shared memory/worker scheduling deferred until measured workloads justify them.
- **Versioned snapshot/command API**, not raw public pointers. C ABI stays internal. Mod hooks resolve synchronously before commands commit. Hooks sort by priority then registration order; cancellation wins, then validated modifications. Mods are trusted same-origin code, not sandboxed.
- **Explicit local PNG import** through file input. File data never uploaded or hosted by the app. GPU textures replaced with cleanup; maximum file and decoded dimensions enforced. Texture packs, mesh/animation decoding, audio and content packs remain visible next milestones.
- **M1 world is deliberately bounded and synthetic**, using real imported art as presentation evidence. An imported item icon is not a faithful character model; the HUD must disclose this. M2 must add real tile assets, collisions, interactions and save/load.
- **Accessibility first:** direction toggle buttons, destination selection, keyboard movement, Stop/Escape and manual takeover invoke the same commands. Accessible HTML position/action status remains outside the canvas.

## M1 integration contract

`engine/src/lib.rs` builds a cdylib at `engine/target/wasm32-unknown-unknown/release/pz_engine.wasm`. Internal exports: `api_version()->u32` (=1), `reset()`, `set_speed(f32)->i32`, `move_to(f32,f32)->i32`, `walk(f32,f32)->i32`, `cancel()`, `step(f32)->i32`, `position_x()->f32`, `position_y()->f32`, `speed()->f32`, `action()->u32` (0 idle,1 destination,2 walking), `tick()->u32`. Initial position (5,5), bounded [0,10] world; speed 1.5 world units/second; speed valid [0.1,10]; nonfinite inputs rejected without mutation. Destination clamps? No: reject outside bounds. Walking normalized, zero direction cancels. Fixed host step 1/60 sec, Rust rejects dt outside (0,0.1]. Reaching destination/edge ends action.

`src/engine.js`: `createEngine(url)` asynchronously instantiates WASM and returns `snapshot() -> {apiVersion,tick,x,y,speed,action}`, `command({type:'moveTo',x,y}|{type:'walk',x,y}|{type:'cancel'})->snapshot`, `setSpeed(number)`, `step(seconds)`, `reset()`; throws on invalid input/export failure. All snapshots detached values.

`src/mods.js`: `createModHost(engine)` returns `api`, `load(url)`, `dispose()`, `command(action)`, `diagnostics()`. Version 0.1.0 public API: `api.version`, `api.movement.getState()`, `api.movement.setSpeed(speed)`, `api.actions.submit(action)`, `api.hooks.beforeAction(callback,{priority=0}) -> unsubscribe`. Callback takes detached command, returns undefined or replacement command or false to cancel; promise rejected. ES module exports `manifest={id,version,apiVersion:'0.1.0',name}`, `activate(api)` returning optional synchronous cleanup function. Unique IDs validated; load failures attributed to module; failed activation unregisters its hooks and restores speed. API delivered here is experimental. Local arbitrary multifile package import/manager comes in M2, not empty APIs now. Example `mods/accessible-walking/main.js` imports `./settings.js`, sets real WASM speed to 2.25 and cleans up.

`src/renderer.js`: `createRenderer(canvas,onError)` resolves renderer with `importImage(file)->metadata`, `render(snapshot)`, `diagnostics()`, `destroy()`. Render can start without asset but acceptance requires actual imported PNG. Metadata includes name,width,height,sourceBytes,textureBytes. Diagnostics includes backend:'WebGPU',adapter info,frame count,asset. Destination coordinate transforms belong in exported `worldFromCanvas(canvas,clientX,clientY)` for host; use [0,10] plane. Device loss reports error and stops; user reload recovers. No silent fallback.

Owner: main agent integrates `src/main.js`, HTML/CSS, package/build/server scripts, documentation and evidence. Independent implementers own engine, renderer and mods files only. All skip tests/build/lint/formatters while editing; integration owner runs checks once afterward. This batching overrides skill test-first execution sequencing, not meaningful regression coverage.
