# Architecture decisions

## 2026-10-12 — Current content-directory architecture

Original game content is provisioned or copied externally into a separate directory, never selected or imported through the web UI. On startup the app fetches `/content/manifest.json` and loads its declared startup resources automatically. Large texture packs use bounded HTTP Range reads rather than whole-bank downloads. The local server mounts `CONTENT_ROOT` at `/content/`; a private static host with byte-range support can serve the same directory beside the asset-free app. No native runtime companion is required.

The version-1 manifest format is `pz-web-content-directory`: `files` contains `{path,size,lastModified,sha256?}` records; `startup` declares `packs`, `cells[{x,y,navigation,header,lotpack}]`, `character{model,idle,walk,texture}` and `spawn`; `mods` contains `{root,kind,files}` records. Paths are relative to the provisioned content root. Build identity stays unknown unless supplied from an observed installation record; a directory or filename alone does not establish a game version.

Content, converted caches and original binaries remain outside Git and application/release artifacts; `content/**` is ignored and must not be staged into `dist` or a release. Provisioning reads the installation without modifying it or native saves. Portable asset transfer means copying this directory or privately hosting it, not browser asset import. Browser save-backup JSON import/export remains separate; receiving devices need matching content and mods. JavaScript packages provisioned under `mods/<folder>` are installed through the existing mod manager; a new install starts disabled and needs explicit checkbox enablement plus reload, while updates preserve the existing enabled flag. Native Lua package discovery does not establish Lua execution or original engine API compatibility.

The optional external helper is `node scripts/provision-content.mjs --source INSTALL --output content`; `--startup-only` copies the bounded startup set, while `--index-only --output DIRECTORY` indexes an already copied directory without reading an installation. `--mods-source USER_MODS` provisions additional mod folders; `--source-build OBSERVED_LABEL` records a supplied observed build label, otherwise `sourceBuild.version` is `unknown`. The Windows wrapper exposes `ProvisionContent -Source INSTALL -Output content` and `-IndexOnly -Output DIRECTORY`. These are provisioning tools, not required companions to browser execution.

The M1 picker-based evidence and contracts below are historical, not the current user workflow or M2 acceptance. Directory autoload is M2 work; this decision records no fresh browser proof and does not lower the full-game destination.

## 2026-10-14 — Source-native queued actions and restoration

One WASM queue owns walk/door/grab/get-up rows, stable action/group/item identities and timing. Original Lua actions remain resident under their exact initiating owner and run unchanged start/update/perform/stop callbacks; completion authorizes the native item/door mutation. Removing a FIFO row is not necessarily object retirement: an in-flight same-ID STOP reply still needs its resident source action.

Public `actions.requestPickup(id)`, `requestDoor(stableId)` and `requestWalk({x,y,z})` return `{accepted,actionId,state}`, never completed-item/door state. `items.pickup` and `world.toggleDoor` use the same admission contract and precommit hooks. Compatible pickups can append groups to an existing Lua-origin action and return its ID. Original menu behavior is not rewritten to match SDK append: `createMenu` refuses speed 0, and source grab selection calls `luautils.walkAdj` without retaining the previous queue.

The page advances one logical native frame per RAF, starting with elapsed 0; it does not drain a timed queue in a fixed-step catch-up loop. Public `time.set('multiplier',0)` freezes source timing without STOP. Manual pause/Escape and existing blur/visibility safety cancellation stop queued work; the automatic 30-second save freezes the session without cancellation.

Optional integrity-covered version-1 `queue` stores native bytes and exact Lua action-to-owner mappings without changing envelope/actor format 2 or ABI 1. Restore stages entities/source geometry before the queue, hydrates genuine supported action classes, and binds supported original continuations after player startup but before publication/first tick. Missing owners, malformed state, unsupported actions and arbitrary nonportable closures refuse rather than inventing callbacks or discarding progress. Original restoration lifecycle details remain in COMPATIBILITY.md.

Lua source-menu open/clear calls are void: discard `sourceMenuMirror`'s HTMLElement return before it reaches Wasmoon, while retaining the JavaScript UI API, callbacks and ownership. Forwarding that DOM graph caused the resolved door-context fault; the opaque-DOM original-source regression failed before/passed after, with no read-only review findings.

Current browser acceptance includes original grabs/current+future groups with exact autosave/reload/completion, veto/FIFO, genuine original door/get-up/audio, 26-item groups20+6, Escape STOP and closed-edge refusal. The group transition retains the same started action/history, resets progress and uses the next group's raw duration. Actual correctly signed malformed-queue import preserved current/previous records and live state; Core-only layout, zero-argument OnPostSave commit ordering and owned STOP-failure safety are proven in STATUS.md. The smoke performed no save after the owned failure. All 13 full-game gates remain open. Engine/Lua share canonical 26-member `MOODLE_TYPES`; `normalItemIcon` follows genuine explicit-Icon/first-IconsForTexture initialization, not unimplemented visual/RNG variants.

## 2026-10-12 — Historical M1 integrated proof

Historical scope: a technical prototype, not a playable port or fidelity claim. The full destination remains M0–M5 in ROADMAP.md. This increment imported real PNG gameplay imagery, rendered it through WebGPU, owned movement/action state in WASM, and loaded an ES-module mod that changed movement speed.

- **Rust 1.96.0, wasm32-unknown-unknown, no crate dependencies.** Installed Windows toolchain, small reproducible C ABI, native rule tests, no generated JavaScript glue. C++ would add compiler setup; wgpu would add unnecessary bindings for this first renderer.
- **Direct JavaScript WebGPU**, one production backend. Real texture uploads, WGSL shaders, render pipeline and queue submission. No WebGL fallback. JavaScript owns browser UI, GPU resources, mod callbacks and asset decoding; Rust owns coordinates, movement target/direction, speed, bounds, tick and cancellation.
- **Single WASM instance on main thread** at fixed 60 Hz. Frame deltas capped at 100 ms; pause/hidden tabs cancel movement and discard backlog, no offline catch-up. Shared memory/worker scheduling deferred until measured workloads justify them.
- **Versioned snapshot/command API**, not raw public pointers. C ABI stays internal. Host and mod-submitted actions use the same synchronous precommit hook pipeline. Hooks sort by ascending priority then registration order; any cancellation wins over replacements. Explicit safety cancellation bypasses veto. Reentrant action submission from a hook is rejected rather than silently bypassing other mods; hooks return replacements or false instead. Delivered UI loads trusted bundled same-origin modules, not a sandbox; dynamic-import origin/CORS rules are not an isolation boundary.
- **Historical local PNG import** used a file input for the M1 proof. File data was never uploaded or hosted by the app. GPU textures were replaced with cleanup; maximum file and decoded dimensions were enforced. This picker path is superseded by directory provisioning/autoload, not retained as future acceptance.
- **M1 world is deliberately bounded and synthetic**, using real imported art as presentation evidence. An imported item icon is not a faithful character model; the HUD must disclose this. M2 must add real tile assets, collisions, interactions and save/load.
- **Accessibility first:** direction toggle buttons, destination selection, keyboard movement, Stop/Escape and manual takeover invoke the same commands. Accessible HTML position/action status remains outside the canvas.

## Historical M1 integration contract

`engine/src/lib.rs` builds a cdylib at `engine/target/wasm32-unknown-unknown/release/pz_engine.wasm`. Internal exports: `api_version()->u32` (=1), `reset()`, `set_speed(f64)->i32`, `move_to(f64,f64)->i32`, `walk(f64,f64)->i32`, `cancel()`, `step(f64)->i32`, `position_x()->f32`, `position_y()->f32`, `speed()->f32`, `action()->u32` (0 idle,1 destination,2 walking), `tick()->u32`. Initial position (5,5), bounded [0,10] world; speed 1.5 world units/second; speed valid [0.1,10]; nonfinite inputs rejected without mutation. Destinations outside bounds rejected, not clamped. Rust validates original JavaScript-double inputs before F32 state conversion, preventing out-of-range values rounding into valid F32 limits. Walking scales finite vectors before normalization to prevent overflow/underflow; zero direction cancels. Fixed host step 1/60 sec, Rust rejects dt outside (0,0.1]. Reaching destination/edge ends action. State snapshots have F32 precision; no promise of infinite precision.

`src/engine.js`: `createEngine(url)` asynchronously instantiates WASM and returns `snapshot() -> {apiVersion,tick,x,y,speed,action}`, `command({type:'moveTo',x,y}|{type:'walk',x,y}|{type:'cancel'})->snapshot`, `setSpeed(number)`, `step(seconds)`, `reset()`; throws on invalid input/export failure. All snapshots detached values.

`src/mods.js`: `createModHost(engine)` returns `api`, `load(url)`, `dispose()`, `command(action)`, `diagnostics()`. Version 0.1.0 public API: `api.version`, `api.movement.getState()`, `api.movement.setSpeed(speed)`, `api.actions.submit(action)`, `api.hooks.beforeAction(callback,{priority=0}) -> unsubscribe`. Callback takes detached command, returns undefined or replacement command or false to cancel; promise rejected. ES module exports `manifest={id,version,apiVersion:'0.1.0',name}`, `activate(api)` returning optional synchronous cleanup function. Unique IDs validated; load failures attributed to module; failed activation unregisters its hooks and restores speed. API delivered here is experimental. `src/mod-manager.js` adds trusted local multifile folder installation, IndexedDB persistence and dependency-ordered startup activation through this same host; the root `mod-worker.js` serves revisioned package URLs. Configuration changes require the next startup; `?safe-mods` skips package imports for recovery. Example `mods/accessible-walking/main.js` imports `./settings.js`, sets real WASM speed to 2.25 and cleans up; its live toggle is disabled while local packages are active to avoid disposing their hooks.

Historical `src/renderer.js` contract: `createRenderer(canvas,onError)` resolved a renderer with `importImage(file)->metadata`, `render(snapshot)`, `diagnostics()`, `destroy()`. Rendering could start without an asset, but M1 acceptance required an actual imported PNG. Metadata included name,width,height,sourceBytes,textureBytes. Diagnostics included backend:'WebGPU',adapter info,frame count,asset. Destination coordinate transforms belonged in exported `worldFromCanvas(canvas,clientX,clientY)` for the [0,10] host plane. Device loss reported an error and stopped; reload recovered. No silent fallback. Current content loading uses the directory contract above.

Owner: main agent integrates `src/main.js`, HTML/CSS, package/build/server scripts, documentation and evidence. Independent implementers own engine, renderer and mods files only. All skip tests/build/lint/formatters while editing; integration owner runs checks once afterward. This batching overrides skill test-first execution sequencing, not meaningful regression coverage.

## M2 navigation and browser-save contracts

The ABI remains 1; world/save exports are additive. An older ABI1 module still accepts the original movement commands, but its wrapper refuses unsupported world/save methods explicitly. Raw memory and scratch pointers are internal host implementation details, never the mod contract.

| Host method | Ownership, validation and side effects |
|---|---|
| `engine.worldImportCell(cellX,cellY,bytes)` | Synchronous; integer cell coordinates −100…100; `Uint8Array` native navigation bytes. Validates BE version1, exactly1024 tagged records and EOF before replay. Rust stages ordered32×32 records of8×8 tiles, committing one256×256 cell only when complete. Cancels active movement on commit; does not relocate actor. |
| `engine.navFlags(tileX,tileY)` | Synchronous detached ground-floor flag byte; integer absolute tile coordinates. `0xFFFFFFFF` means unloaded. SOLID1, WALL_N2, WALL_W4, WATER8, ROOM16, VOID32. Navigation is not visible tile geometry or native multilevel parity. |
| `engine.worldBounds()` | Detached `{active,minCx,minCy,maxCx,maxCy,cells}` in cell coordinates; gaps inside bounds remain unloaded/blocked. |
| `engine.worldReset()` | Drops committed/staged cells and routes, cancels movement, preserves actor coordinates/speed/tick. `reset()` additionally restores initial actor state. |
| `engine.saveState()` | Detached `{version:1,values:[x,y,speed,targetX,targetY,headingX,headingY,action,tick,worldActive]}`. Cells are supplied separately by the host. |
| `engine.loadState(state)` | Synchronous atomic validation: finite/ranged scalars, integer action/tick, normalized or zero heading, matching world mode, loaded passable coordinates. Destination restores reconstruct a legal route; refusals leave actor/path unchanged. |

Movement uses WASM edge collision, direct-segment checking and four-neighbour A* with at most200000 expansions. Imported navigation covers ground floor only. SOLID/VOID block entry; north/west bits block shared edges. This format-derived model is not a native-behaviour equivalence claim. Host map placement near a cell centre is an explicit browser approximation until original spawn definitions are loaded.

`src/saves.js` exposes `createSaveStore({engineSource,appVersion})`: `save(engine,context)` captures a detached tick-boundary snapshot, serializes writes and commits `{current,previous}` atomically in IndexedDB `pz-web-saves` v1; `load(id='autosave')` builds a fresh WASM instance and returns `{engine,record,recovered,recoveryReason?}` without mutating the live session. Failed newest restores may recover the prior committed revision, never uncommitted staging. `list()` returns slot metadata; `close()` releases storage; `diagnostics()` reports availability and never guarantees browser durability.

`exportSave(id)` produces a committed JSON `Blob`; `exportLive(engine,context)` creates a validated backup without IndexedDB, including when persistence is denied/full. `importSave(file)` validates and stages before inserting a new UUID slot, never overwriting an existing one. The `pz-web-save` v1 envelope records engine ABI/state version, application version, navigation cells, content-pack/mod provenance and opaque mod namespaces; canonical SHA-256 detects accidental corruption, not malicious authorship. Size cap16MiB and64 navigation cells. Unknown envelope versions are refused; no fabricated migration for an unknown schema.

UI autosave starts only after explicitly creating/loading/saving a session. A fresh page cannot overwrite retained saves merely by waiting. The UI checks saved versus running mod IDs/versions before publishing a restored session; missing/incompatible mods leave the current game intact and preserve saved namespaces. Rendering content is not yet embedded in this navigation save: receiving devices must provision matching visual assets separately. Storage eviction/deletion recovery requires an exported backup. Native saves remain unsupported.
